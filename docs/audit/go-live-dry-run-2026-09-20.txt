2. Terraform plan
------------------
A `terraform plan` run from THIS machine cannot reach a verdict: `infra/providers.tf`
configures the Stripe and Cloudflare providers from `STRIPE_API_KEY` /
`CLOUDFLARE_API_TOKEN` in the environment, and getting either of those onto this
machine means reading a live secret's value — which this task's rule forbids and which
CLAUDE.md's GitOps rule reserves for CI alone ("terraform apply is CI's alone... You
never touch secrets, never run terraform apply"). `terraform -chdir=infra init` and
`terraform state show <address>` do NOT need those credentials (they read the GCS
state file, not the live APIs), and both ran clean above with no credentials at all.
A plan/apply that talks to the actual Stripe and Cloudflare APIs only ever runs inside
deploy.yml, with GitHub's own masked secrets.

So the closest honest substitute is the real plan+apply CI already ran, on the current
main HEAD (1b06e37, this morning, run 35570828196 — `gh run view 35570828196 --log`):

    Terraform will perform the following actions:

      # google_cloud_run_v2_service.api will be updated in-place
      ~ resource "google_cloud_run_v2_service" "api" {
          - client = "gcloud" -> null
          ...

    Plan: 0 to add, 1 to change, 0 to destroy.

This is NOT drift in the Stripe objects — 0 to add, 0 to destroy, and no stripe_*
resource is touched. The one change is a known, harmless oscillation: the `gcloud run
deploy` step later in the SAME job stamps a `client=gcloud` annotation onto the
revision it deploys; Terraform's own config never sets that field, so the very next
apply always finds it set and reverts it to null. This has nothing to do with the live
switch and does not need Kevin's attention; it recurs on every ordinary deploy,
including the one this task's own push triggers (see HANDOFF.md for that run's log
once watched). No Stripe resource plan showed any change in this or the prior five
deploys since task 07 (05 through 16 all deployed green with no infra/*.tf edits in
that span — `git log --oneline -- infra/` shows the last actual infra/*.tf change
predates the live switch).
